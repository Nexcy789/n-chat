# 架构

DSH（DeepSeek Harness）上跑的多人群聊。每个角色一份独立人格和一套独立情绪，
由一个协调器决定谁接话；没人说话的时候，由心跳决定要不要主动开口。
网页和 Android 共用同一份前端。

出问题先看第 9 节「已知问题」。

## 1. 组成

| 部分 | 位置 | 作用 |
|---|---|---|
| DSH 主进程 | 安装目录 | 跑所有插件，默认端口 3090 |
| dsh-webchat | `plugins/dsh-webchat` | 群聊服务端 + 前端（端口 4200） |
| dsh-voice | `plugins/dsh-voice` | Breeze TTS 接入（端口 8137） |
| dsh-cover | `plugins/dsh-cover` | 翻唱（需要本机装 SeedVC） |
| dsh-skin-deepglass | `plugins/dsh-skin-deepglass` | 深色玻璃皮肤，只注入 CSS |
| Android 壳 | `android/` | WebView 加载前端 + 推送 + 相册保存 |
| 人格 | `workspace/<角色>/AGENTS.md` | 每人一份，启动时读 |

画图（豆包）、B 站字幕、长期记忆这几块靠另外的插件，不在本仓库里。

## 2. 目录

```
<项目根>/
├─ data/
│  ├─ webchat/            会话数据（chat.jsonl / state.json / moods.json / uploads / audio）
│  ├─ sessions/           DSH 的会话历史（zstd 压缩）
│  ├─ attachments/v1/     附件（objects/ 图片，file-objects/ 普通文件）
│  └─ profiles/<profile>/ cordis.patch.yml 所在处
├─ plugins/dsh-webchat/   主插件
│  ├─ lib/index.js        服务端（约 2000 行）
│  ├─ lib/mood.mjs        情绪模型（七维）
│  ├─ lib/mood-driver.mjs 情绪驱动，按角色包一层倍率
│  ├─ lib/impulse.mjs     静默加成（安静越久，开口分越高）
│  ├─ lib/coordinator.mjs 协调器（谁接话）
│  ├─ lib/policy.mjs      开口判定 / 拒绝词
│  └─ web/index.html      前端（单文件，无构建）
├─ workspace/
│  ├─ <角色>/AGENTS.md    人格
│  └─ refs/               参考图（画图插件用）
├─ android/               Android 工程
└─ scripts/               启动 / 停止 / 打包
```

路径默认都相对项目根算，根由环境变量 `NCHAT_HOME` 指定；配置里写绝对路径也认。

## 3. 一条消息的完整路径

```
用户发消息
  → onUserMessage：落库、更新情绪、detectTease
  → 等 mergeWindowMs（默认 4.5 秒），合并连发
  → deliverBatch：协调器决定谁接
  → speak()：
      按游标取 backlog（最多 80 条，取最近）
      拼场景行（群聊/私聊 + 当前时间）
      拼心情段（只在档位变化时）
      拼消息行（带时间戳、[语音]/[发了一张图] 标记）
      agent.followup()
  → session/event 流式回来：
      累积正文 → 合并窗口（普通 1.5 秒 / 等工具 90 秒）
      扫输出目录插新图（只插一张）
      flushTurn：切分、剥 [语音] 标记、逐条落库
  → 前端每 1.6 秒问一次 /api/state?slim=1（只回版本号），版本变了才拉全量快照
```

## 4. 情绪系统

### 4.1 七维

| 键 | 含义 | 范围 |
|---|---|---|
| `missing` | 想他 | 0–1 |
| `jealousy` | 吃醋 | 0–1 |
| `warmth` | 暖意 | 0–1 |
| `worry` | 担心 | 0–1 |
| `boredom` | 闲 | 0–1 |
| `lust` | 亲密 | 0–1 |
| `annoyanceDebt` | 恼火 | **0–60 点**（不是百分比） |

`lust` 可以整个关掉：`lust: { enabled: false }`。

### 4.2 自然演化

`moodFillHours` 默认 6，折算成基准 16.7%/小时。

| 维度 | 每小时 |
|---|---|
| 想他 | +16.7%（23:00–03:00 ×1.6） |
| 吃醋 | +0.8%（基准 × 0.05，只做缓慢发酵） |
| 暖意 | −16.7% |
| 担心 | 凌晨 0–5 且一小时没动静 +16.7%，其余 −16.7% |
| 闲 | +8.3%~16.7%（想他越强涨得越快） |
| 亲密 | 只落：−`teaseStep/decayHours`，即 −7.5%/小时 |
| 恼火 | −10 点/小时 |

### 4.3 事件

| 触发 | 变化 |
|---|---|
| 用户说任何一句 | 想念 −25%、吃醋 −10%、恼火 −20 点、闲 −20%、担心 −20% |
| 说甜话 | 暖意 +30%、恼火 −8 点、想念 −10%（点名给点名者，否则全体） |
| 点名别人 | 未点名者吃醋 +14% × 倍率 |
| 她说完 25 分钟没人接 | 恼火 +6 点、想念 +5% |
| 她说话没人应 | 想念 +16%、担心 +10%、恼火 +3 点（上限 25） |
| 她回话 / 主动开口 | 想念 −10% |
| 命中挑逗词 | 亲密 +15%（至少推到 20%） |
| 被拒绝 | 恼火 +30 点 |

### 4.4 主导与语气

`score = max(七维)`，超过 55 才允许主动开口。恼火是 0–60 点，先折算成百分比再一起比（60 点 = 100%）。

| 主导 | 语气 | 强度档 |
|---|---|---|
| 想他 | `clingy` | ≥0.75 强 / ≥0.5 中 / 否则轻 |
| 吃醋 | `pouty` | 同上 |
| 暖意 | `warm` | |
| 担心 | `worried` | |
| 闲 | `light` | |
| 亲密 | `flirty` | |
| 恼火 | `sulky` | |

心情段按 `${主导}|${强度}|${语气}` 签名去重，**变了才注入一次**。群聊和私聊各算各的签名。

### 4.5 亲密这一维的两段

```
被推一次：+15%，翻到 decay
decay：每小时 −7.5%，落到 20% 停住，翻回 grow
grow：不涨
```

参数：`floorPercent 20` / `teaseStepPercent 15` / `decayHours 2`。

### 4.6 每人的倍率

写死在 `mood-driver.mjs`，三个示例角色各一套：

| | 角色一 | 角色二 | 角色三 |
|---|---|---|---|
| 想念 | 1.0 | 1.15 | 0.9 |
| 吃醋 | 1.3 | 0.5 | 1.5 |
| 暖意增长 | 1.0 | 1.15 | 0.85 |
| 暖意冷却 | 1.0 | 0.75 | 1.2 |
| 担心 | 1.25 | 1.0 | 0.9 |
| 闲 | 1.1 | 0.85 | 1.15 |
| 消气 | 1.0 | 0.9 | 0.75 |

配置里写 `moodRates: { role3: { jealousy: 2 } }` 可以覆盖单项。

## 5. 协调器

### 5.1 四条路（按优先级）

```
私聊            → 直接回
@所有人         → 全部接，顺序随机
点名            → 被点者先接；点两个时第二个 50% 也接
其余            → 掷骰
```

掷骰前排除连续说了 `maxConsecutive`（2）条的人。每人按 `talkativeness` 独立掷
（示例值 0.7 / 0.6 / 0.8），三个人期望 2.1 人接，约 2.4% 的概率没人接。

### 5.2 掷中之后谁先说

加权抽签，不取最高分。

```
W = 0.4 × 情绪分 + 0.6 × 沉默分 + 0.02

情绪分 = max(七维) / 100
沉默分 = 10 分钟内说过 → 0
         10–60 分钟 → (分钟数 − 10) / 50，线性涨到 1
         超过 60 分钟 → 1
```

抽签按 W 的比例分配概率，分高的人更常被抽到，但不会垄断。

为什么不用「最高分先说」：那是正反馈——分高 → 被选中 → 说得更多 → 分更高，
实测一个人能连回一整晚。改成抽签之后的分布（300 次模拟）：

| 场景 | 角色一 | 角色二 | 角色三 |
|---|---|---|---|
| 角色一刚说过，另两个两小时没说话 | 13% | 39% | 48% |
| 三个都刚说过 | 48% | 24% | 29% |

### 5.3 第二个人

`secondSpeakerChance`（0.2），从剩下的人里按同样权重抽。

## 6. 主动开口

### 6.1 三道闸

按顺序判，任一道不过就不开口。

| 闸 | 参数 | 默认 |
|---|---|---|
| 每日额度 | `maxPerDay` | 8（所有人共享，按本地日期换天） |
| 静默时段 | `quietHours` | `['01:00-08:00']` |
| 全局冷却 | `globalCooldownMin` | 105 分钟上下浮动 14%（共享） |

### 6.2 两种触发

**问候窗口**：07–09 / 11:30–13 / 18–20，每个窗口每天一次，35% 概率，随机延迟 0–3 分钟。

**情绪自发**：群里安静满 `impulseQuietMin`（12 分钟）＋（情绪分 + 静默加成）超过
`impulseThreshold`（55）＋每人冷却 `impulseCooldownMin`（45 分钟），随机延迟 0–2 分钟。

**静默加成**（`impulse.mjs`）：安静 12 分钟之前是 0，12→90 分钟线性涨到 `quietBonusMax`（30 分），
之后封顶。12 分钟那道硬门槛只挡住「刚聊完」，过了之后的差别全靠这段加成补。

这套数是照着「每 1.4–2 小时一条」定的：安静一个半小时加满 30 分，情绪只要 25 就够 55。

**轮空补偿**（`missedBonusStep` / `missedBonusMax`）：连着几轮别人开口、她没轮上，
这一次的开口分乘 (1 + 轮空次数 × 0.25)，最多 ×1.75；开一次口就清零，另外两个 +1，跨天也清零。

这是正反馈的另一半：冷却只负责压住刚说完的人，压不动作息最慢的那个。
想念倍率 0.9 的角色长期排第三，模拟一天 8 次一次都轮不到。
加补偿前后（同一套参数各跑 3 次）：0 次 → 3 次，三个人变成 2/3/3。

全局冷却兜住下限，每次现掷 ±14%（90–120 分钟），不会精确得像闹钟。
排上之后 5 分钟内不再排第二个（`pendingImpulseAt`）。

### 6.3 速率估算

理论上限：按 105 分钟冷却算一天最多 13 次，但每日额度 8 次封顶、夜里还有静默段，
实际 8 次左右。均值 5 次上下，间隔 3–5 小时。受用户说话频率影响很大——
每说一句，想念 −25%，重新攒。

## 7. 媒体

### 7.1 语音（Breeze TTS）

- 插件 `dsh-voice`，默认端口 8137
- 触发方式：她在句首写 `[语音]`，剥掉标记后照常存文字，另生成一条语音
- `cfg_scale: 2.0`（Breeze 的默认值，情绪标签要 2–3 才生效）
- 支持标签：`[叹气]` `[笑]` `(sigh)` `(laugh)` `(cough)` `(clears throat)`
- 长度上限 90 字，超了不合成
- 音频接口支持 Range（206），手机上能拖进度条

### 7.2 画图

豆包那条链路依赖本机客户端，插件不在本仓库。约定是：

- 参考图放 `workspace/refs/`，人格里写路径
- 产物落在 `workspace/<角色>/` 下的图片目录
- 出图后自动插进聊天（`collectPainted`），一轮只插一张

### 7.3 视频与字幕

同理，B 站相关的插件独立。约定是抽帧上限 9 张、默认拼成一张（3×3 / 3×2 / 3×1），
插进聊天只取第一张。

## 8. 前端与 App

### 8.1 前端

单文件 `plugins/dsh-webchat/web/index.html`，无框架无构建。
改完要同步到 `android/app/src/main/assets/index.html`（两个文件必须一模一样）。

主题变量：`--bg` `--panel` `--line` `--text` `--dim` `--accent` `--me`。

### 8.2 App

- WebView 加载本地 `index.html`，接口走 `/api/*`
- 桥：`NChat`（服务器地址 / 推送 / insets）、`AndroidSaver`（保存文件 / 保存图片到相册）
- 保存到相册：`saveImage(name, b64)` → `MediaStore.Images` + `Pictures/NChat`
- 设置页只在没存过地址时出现，地址存 `SharedPreferences` + `localStorage` 两份
- 服务端地址由 `/api/state` 的 `hosts` 给（组网地址优先，其次局域网）

## 9. 已知问题

### 9.1 `maxPerDay` 曾完全失效

`flushTurn` 里调 `mood.onSheSpoke(turn.roleId)` 少传了第三个参数 `spontaneous`，
`global.count` 永远是 0，额度这道闸门等于不存在。

修法：`onSheSpoke(roleId, now, spontaneous)`，`spontaneous` 由 `modeOfReason(turn.reason)` 判
（问候 / 自发算，回话不算），而且**只在这一轮的第一段记一次**——
一段话切成三条只该吃一次额度，按段记会一次吃掉三格。

### 9.2 图片投递

- 发图的链路：`makeImageBlock` 手写文件到 `attachments/v1/objects/<2>/<sha>`
- 图片走 `objects`，普通文件走 `file-objects`，两个不能混
- 混错的后果是所有带图的请求 `DeepSeek Messages transport failed`，每条历史消息每轮都失败
- 补救：把图从 `file-objects` 复制到 `objects` 就能恢复历史
- 抽帧的 image block 开着：`nativeImage: true` 时，她这一轮调过工具、
  或她自己 3 分钟内发过图，就会把最近一张带进投递

### 9.3 还没动的

| 现象 | 卡在哪 |
|---|---|
| 「一个人最多连说两条」从来没生效 | `coordinator.trailingRun()` 从消息流末尾往回数，但末尾永远是用户刚发那句，三个人都算出 0。现在靠掷骰权重里的抑制，不打算修 |
| 老消息里的图会突然裂掉 | `pruneUploads()` 只留最近 500 张，不看是否还被消息引用 |
| 群名 / 表情包概率 / 问候概率改配置不生效 | 这些键没进 `normalizeConfig` 的白名单 |

**死代码**（不影响运行，改动前先看一眼）：`attachment.js` 的 `writeDshAttachment` 没有调用点；
`policy.mjs` 二十来个导出只用了 4 个；`flushTurn` 里表情包 + 点名那段写了两遍（前一处永远进不去）；
前端的 `readAt` 只存不用。

## 10. 设计取舍

几条踩过的坑。

**合并窗口**。用户连发几条如果逐条投递，模型会逐条回，像打乒乓。攒 4.5 秒合成一批，语境才对。

**心情段去重**。每轮都注入会把模型逼成复读机——它会复述「我现在很吃醋」。
按签名去重，只在档位真的变了的时候注入一次。

**道别静音**。做过「用户说晚安就闭嘴 X 小时」，实测误判率高（一句「睡了」也可能是午睡），
而且用户回来时它还在静默。删掉了。

**状态文件原子写**。`moods.json` / `state.json` 直接写会在断电或强杀时留下半个文件，
读的时候整份丢失，情绪归零。现在全部走 `writeFileAtomic`。

**开口时机不用最高分**。见 5.2。
